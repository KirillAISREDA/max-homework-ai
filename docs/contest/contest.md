## КЛЮЧЕВОЕ: методика подсчёта «обращений» (Прил. 2, п. 2.2)

Обращение = **вызов Решением любого компонента**: LLM-ядро, инструменты (API, другие агенты), навыки/скилы (специализированные инструкции над моделью), системы фонового исполнения. Пример из Положения: одна задача ИИ-консьержа = 5 обращений (модель + 4 инструмента/скила).

**Следствие для нас**: одна проверка домашки нашим пайплайном (Vision 1–2 + Solver ×7 + Validator-вызовы + Classifier + Tutor 8–12 + Generator + Student Model) — это **десятки обращений на пользователя в день по конкурсной методике**. Архитектура буквально создана под номинацию «Высокочастотная поверхность».

⚠️ Это **не то же самое**, что наша внутренняя метрика из architecture.md §1.1/§11.6 (обращение = действие пользователя, `user_initiated=true`, технические вызовы не считаются). Считаем ОБЕ: внутреннюю — для продукта, конкурсную — для отчётности. В событиях/логах каждый вызов компонента должен иметь: `trace_id, user_id (обезличенный), timestamp, тип вызова (компонент), результат, код ошибки` — ровно то, что требует антифрод (Прил. 2, п. 5).

Из зачёта исключаются вызовы тестов/отладки → **прод-трафик и тестовый трафик разделять на уровне логов с первого дня** (флаг/отдельная среда).

## Требования, влияющие на разработку

1. **Открытый контур**: рабочая среда Решения, репозиторий кода и аналитика с доступом для Организатора. Наш публичный GitHub уже соответствует; аналитика — предусмотреть дашборд/выгрузки.
2. **Решение с нуля в период конкурса** (п. 3.6): репозиторий создан 30.08.2026, вся разработка в период — ОК. Участник гарантирует исключительные права на РИД.
3. **Раскрытие компонентов** (п. 5.3): вести реестр сторонних библиотек, моделей, API (pyproject + docs).
4. **Антифрод** (п. 5.4, Прил. 2 п. 5): никакого стимулированного/тестового трафика в метриках; полные логи, источники трафика, обезличенные id, типы вызовов, коды ошибок — по запросу.
5. **ПДн** (п. 5.6): законность обработки данных пользователей — на нас (уже проектируем под 152-ФЗ, дети → согласие родителя).
6. **Отчуждение РИД** Сбербанку — условие получения выплаты Победителем (код, документация, архитектура, инструкции по развёртыванию).
7. **UX/UI-номинация** (Прил. 2, п. 2.3): понятность сценария без инструкций, скорость до первого результата, обработка ошибок и некорректного ввода, прозрачность действий, целостность визуального языка, адаптивность. Наши FSM-сценарии, честные статусы («проверю через ~2 минуты»), обработка «переснимите фото» — прямо по критериям.

## Влияние на план (architecture.md §10)

- План «6 недель до пилота 10–20 семей» уплотняется: к **15.10** нужны **70 реальных пользователей** и 30 интервью, не 10–20 семей.
- Ноябрь — не «после пилота», а боевой Зачётный период с DAU ≥ 1000 устойчиво: маркетинг/каналы привлечения нужно планировать уже на этапе 1 (концепция вывода на рынок — обязательный артефакт этапа 1).
- Мониторинг вызовов компонентов (метрики+логи из архитектуры §9) — не «неделя 5», а к началу пользовательского трафика.
