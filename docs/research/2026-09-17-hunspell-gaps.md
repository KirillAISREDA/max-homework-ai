# Спайк: заполнение пропусков «вставь буквы» по словарю Hunspell (ru_RU)

Дата: 2026-09-17. Код: `spikes/hunspell_gaps/` (`gaps.py`, `exercises.json`).

## Выводы (кратко)

- На 25 реальных упражнениях 2–4 класса (227 пропусков) словарь Hunspell `ru_RU` однозначно
  восстанавливает **164 пропуска из 227 (72,2 %)**, и все 164 совпадают с эталоном учебника
  (0 ошибок).
- **63 пропуска (27,8 %)** дают 2 и более словарных кандидата — нужен контекст (LLM или
  синтаксическая проверка); примеры и категории — ниже.
- Пропусков **без единого словарного кандидата не встретилось (0/227)** — но это, вероятно,
  оптимистично для будущей реальной нагрузки: см. «Ограничения».
- **Решение**: вердикт `verified`, когда `fill_gap` возвращает ровно один кандидат; при 0 или ≥2
  кандидатах — вердикт не выше `candidate`, фрагмент уходит в LLM с контекстом предложения и в
  очередь проверки. `fill_gap(pattern) -> list[str]` из спайка переносится в этап 3 как есть.

## Типичные неоднозначности (примеры из реального прогона)

**1. Омофоно-подобные пары слов** — разные слова, оба реальны, только контекст решает:

- `щ_ка` → щека / щука (эталон: щука)
- `п_года` → пагода / погода (эталон: погода)
- `б_лет` → балет / билет (эталон: билет)
- `л_са` → лиса / леса — встретилось дважды в одном упражнении с разными эталонами
  («несёт меня **лиса**» и «за дальние **леса**»): один и тот же паттерн `л_са`, оба кандидата
  реальны, эталон разный от предложения к предложению — без контекста не решить.
- `к_вер` → кивер / ковер (кивер — редкое слово, но оно есть в словаре)

**2. Формы одного слова с безударным окончанием** — нужна грамматика/синтаксис, не только словарь:

- `весел_` → весела / весели / весело / веселы / веселю / веселя (6 форм одной леммы)
- `хол_дн_` → холодна / холодно / холодны
- `п_ля` → паля / пиля / поля / пуля / пыля / пяля (6 кандидатов на «поля»)
- `р_ка,` → рака / река / рока / рука / рыка (5 кандидатов)

**3. Корневая омонимия согласных на конце/середине слова** (проверяемые/непроизносимые согласные):

- `лё_.` → лёг / лёд / лён / лёт (эталон: лёд)
- `сне_.` → снег / снес (эталон: снег)
- `берё_` → берёг / берёз / берём / берёт (эталон: берёз)

**4. Многобуквенный пропуск в одном слове** (`осе__ие`, два `_` подряд): осевшие / осекшие /
осенние — та же природа неоднозначности, просто больше кандидатов из-за большего пространства
перебора при переборе двух букв сразу.

Именных собственных (типа примера из брифа «м_шина: машина/мишина») в выборке не оказалось —
упражнения о природе и быту, не о людях. Логика та же, что и в пункте 1: `dictionary.lookup`
вызывается по `candidate.lower()`, то есть словарь **регистронезависим**, и `Мишина` (фамилия) от
`машина` (слово) он не отличит — при попадании в реальные фото такие случаи нужно ловить отдельно
(например, эвристикой «первая буква предложения/после точки» не поможет, если имя стоит в середине
фразы).

## Ограничения спайка

- Все 227 пропусков проверялись на **уже правильном** окружающем тексте (упражнения набраны вручную
  из печатных источников). В реальном пайплайне вокруг пропуска будет текст **с OCR-шумом** и
  фото почерка ученика; ошибка OCR соседних букв может: (а) сделать верный кандидат несловарным →
  ложный `none`, или (б) случайно совпасть с другим словарным словом → ложный `single`, который на
  самом деле неверен. Этот риск здесь **не измерен** — нужен отдельный прогон на транскрипциях
  реальных фото (см. TODO проекта).
- Hunspell не учитывает частотность слов — `кивер`, `рока`, `рэкета` считаются такими же
  кандидатами, как частотные слова. Взвешивание по частотности могло бы снизить долю `ambiguous`,
  но не реализовано в спайке (не требовалось по брифу).
- 0/227 пропусков без кандидата — вероятно, оптимистичный результат: слова уровня 2–4 класса почти
  всегда есть в ru_RU. Редкие термины, неологизмы, диалектизмы, имена и опечатки OCR дадут `none`
  заметно чаще на реальных фото.

## Источники и ограничения по набору упражнений

Набрано **25 из 30** целевых упражнений (83 %). Не хватило времени найти ещё 5 с одновременно
точным текстом пропусков **и** опубликованным эталоном ответа: многие карточки на nsportal/infourok
дают текст без ответов, а ГДЗ-сайты обычно дают ответ к финальному (беспропускному) упражнению
учебника, а не к дидактической карточке с пропусками. Решено не добивать до 30 неточно
восстановленными или выдуманными примерами — честность важнее ровного числа. Полный список
источников с точными ссылками/номерами — в `exercises.json` (поле `source` на каждую запись):
nsportal.ru — 7 карточек/страниц, infourok.ru — 3 страницы, videouroki.net — 1, budu5.com (ГДЗ к
рабочей тетради Канакиной) — 1 упражнение с официальным номером и страницей.

## Решение

1. **`verified`** — только когда `fill_gap(gap)` возвращает **ровно один** кандидат. Совпадение
   длины уже гарантировано алгоритмом (по одной букве на каждый `_`), дополнительная проверка длины
   не нужна.
2. Если кандидатов **0 или ≥2** — вердикт не выше `candidate`: фрагмент (пропуск + окружающее
   предложение) уходит LLM с просьбой выбрать из словарного списка кандидатов (когда список не
   пуст) или восстановить слово свободно (когда он пуст), и кладётся в очередь ручной проверки — как
   и предписывают глобальные ограничения проекта (непроверенный эталон даёт не выше `candidate`).
3. `fill_gap(pattern) -> list[str]` из `spikes/hunspell_gaps/gaps.py` — рабочий алгоритм для этапа 3,
   переносится как есть; при переносе обернуть кэшем по паттерну (перебор растёт как 33^n — уже при
   n = 2 в спайке это 1089 комбинаций на одно слово, при n ≥ 4 нужно будет ограничивать или
   отказываться от полного перебора).
4. Перед продовым включением — прогнать тот же алгоритм на **реальных OCR-транскрипциях фото**
   (не идеальном наборном тексте), чтобы измерить долю ложных `verified` от шума распознавания, а
   не только от языковой неоднозначности, которую измерил этот спайк.
