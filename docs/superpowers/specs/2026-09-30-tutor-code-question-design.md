# Разбор ошибки: вопрос задаёт код. Дизайн

Дата: 2026-09-30. Статус: направление согласовано с Кириллом в чате 30.09 (кусок 2 из 3: проверка →
разбор → сводка), текст ждёт вычитки. Связанные документы: `docs/architecture.md` §3.2–3.3 (FSM,
тьютор), `2026-09-30-math-misread-guards-design.md` (кусок 1).

## 1. Что случилось

Живой разбор 30.09 (№ 2.181). Модель спросила «что получается при вычитании в пункте а)?». Ребёнок
дважды верно ответил «36» и дважды услышал «пересчитай». На третьем ответе модель сама сказала
«Молодец!», а код разбор не закрыл: он ждал другое число. Чат остался в режиме разбора, продолжения
не было. Причины в `pipeline/tutor.py`:

1. Вопрос формулирует модель, а закрывает разбор сверка кода с одним числом (`expected`).
2. Верное промежуточное значение неотличимо от неверного ответа. Уровень подсказки растёт, а модель
   (промежуточных значений она не видит — так задумано) считает ответ ошибкой.
3. Похвалу пишет модель: на уровне 3 эталон у неё в промпте, и «Молодец!» она говорит по своей
   сверке. Выхода из разбора после уровня 3 нет.
4. Место ошибки модель получает как «шаг 2», номер строки, и сопоставила его не с той строкой.

## 2. Решения

| Вопрос | Решение |
|---|---|
| Кто задаёт вопрос | Код, фиксированной фразой после подсказки модели. Модель пишет только подсказку, без вопросов (промпт `tutor/v2`) |
| Промежуточное значение | Совпало с действием ошибочной строки — «верно, дальше»: уровень не растёт |
| Похвала | Только когда код засчитал ответ (или верное действие); иначе похвала в реплике → перегенерация, затем безопасная фраза |
| Место ошибки для модели | Номер и текст ошибочной строки ребёнка |
| Выход | Решение показано (уровень 3), следующий ответ снова неверный — код называет ответ и закрывает разбор как «показал решение», не «исправил сам» |
| Что дальше | После любого завершения: остались ошибки — «Разберём ещё одну ошибку?» с кнопками, не осталось — «Пришли фото следующего задания — проверю 📸» |

## 3. Дизайн

### 3.1. Вопрос от кода

`TutorSession.target_line` — ошибочная строка ребёнка (после уточнения пункта — строка с печатным
выражением). Вопрос:

- строка с меткой пункта — «Сколько получается в пункте а)? Напиши ответ числом.»;
- строка с переменной — «Чему равно x? Напиши ответ числом.»;
- иная строка — «Сколько будет 700 − 400? Напиши ответ числом.» (левая часть — запись самого
  ребёнка, эталона она не раскрывает);
- строки нет (ошибка только в ответе) — «Какой ответ получается в задаче? Напиши его числом.»

Вопрос дописывается ко всем репликам, кроме похвалы за засчитанный ответ и реплики, закрывающей
разбор.

### 3.2. Промежуточные значения

`mathparse.action_values(expression)` — значения всех действий выражения: дерево SymPy без
вычисления, у сумм и произведений из нескольких слагаемых — частичные результаты слева направо.
«39452 − 16452 : (300 − 264)» → 36, 457, 38995. Ответ ребёнка совпал с действием левой части
`target_line` и не совпал с целью → уровень не растёт, число попадает в `known_values` (фильтр утечек
его больше не прячет), модель получает ситуацию «ученик верно посчитал действие: 36; коротко отметь и
подскажи следующий шаг, не называя его результата». Значения действий, которых ребёнок ещё не назвал,
фильтр утечек считает секретами наравне с эталоном.

### 3.3. Похвала

- Контекст неверного ответа: «Ответ ученика не верный — не хвали и не говори, что задание решено».
- Фильтр реплики без засчитанного ответа и без верного действия: «молодец», «правильно», «верно»,
  «отлично», «умница», «так держать» (кроме «неверно», «правильно ли», «верно ли») → одна
  перегенерация со «СТОП», затем безопасная фраза.

### 3.4. Выход после уровня 3

Ответ приходит, когда `hint_level` уже 3 (решение показано), и он снова неверный: без вызова модели код
отвечает «Ничего страшного 🙂 Верный ответ: <цель>. Запиши его в тетрадь.» и ставит `closed`.
Обработчик переводит чат в `review`, индекс задания — в новый список `shown_indices` (кнопка
«Разобрать» по нему больше не показывается), событие `tutor_closed` с `outcome="shown"`. `error_fixed`
и сообщение родителю о разобранной ошибке — только за ответ, засчитанный кодом.

### 3.5. Совместимость

Новые поля `TutorSession` и `ChatState` — с умолчаниями: сессии в Redis от прошлого релиза читаются
(без `target_line` вопрос — «Какой ответ получается в задаче?»). Разбор орфограммы (`_word_reply`)
не меняется; его промпт остаётся `ru_tutor/v1`.

- `tests/test_bot*.py`: закрытие разбора кодом, `shown_indices`, «что дальше» в обоих вариантах.
