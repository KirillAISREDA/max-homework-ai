# Каркас предметов, база знаний, русский и английский язык — дизайн

Дата: 2026-09-16. Статус: согласован с Кириллом по разделам (брейншторм 16.09), ждёт вычитки.
Связанные документы: `docs/architecture.md`, `docs/research/2026-09-13-ru-handwriting-ocr.md`,
`docs/superpowers/specs/2026-09-14-onboarding-design.md` (каталог предметов §5, профили §6).

## 1. Контекст и цель

Бот «Домашка» проверяет математику: фото тетради → распознавание → эталон солвера → пересчёт SymPy →
вердикт → разбор с тьютором. Все остальные предметы каталога показаны как «скоро». Решение 16.09: к
15.10.2026 (сдача этапа 1 Sber500xDisrupt) в проде работают **русский язык** и **английский язык** в
минимальных формах, а сама проверка устроена так, чтобы каждый следующий предмет стоил в разы дешевле
первого.

Цель документа — принципы проверки для любого предмета, контракт предметного модуля, база знаний,
минимальные формы русского и английского, порядок работ.

## 2. Решения

| Вопрос | Решение |
|---|---|
| Источник эталона для предметов без пересчёта | Фото учебника + накапливаемая база заданий; ответы выводим сами (LLM + детерминированная проверка), чужие ответы (ГДЗ) не парсим |
| Формы домашки по иностранному языку | Все четыре (упражнения с однозначным ответом, словарь, перевод/свободные ответы, сочинения), но с разной силой вердикта; к 15.10 — только первая |
| Содержимое базы знаний | Задания учебников из фото учеников, наши проверенные ответы, правила по классам, словари |
| Срок | Русский и английский к 15.10, параллельно с этапами 3–5 онбординга |
| Что откладывается первым при нехватке времени | `verified` для английского (остаётся `candidate`), затем кропы слов в уточняющих вопросах |

## 3. Принципы для всех предметов

1. **Цель — научить, не решить.** Подсказки 0→3, ответ только на уровне 3 (инвариант `CLAUDE.md`).
   Для форм без однозначного ответа (сочинения) ответа нет, только разбор «что улучшить».
2. **Два независимых источника: «как написано» и «как должно быть».** «Как написано» даёт инструмент,
   который не исправляет ребёнка: посимвольный OCR без языковой модели для языков (исследование 13.09:
   GigaChat-vision скрывает 78–80 % ошибок ученика), двухэтапный vision для математики. «Как должно
   быть» — эталон: фото учебника, база заданий, наш выведенный и проверенный ответ, словарь, правило.
   LLM соединяет их только там, где детерминированного сравнения нет, и тогда вердикт слабеет.
3. **Сила вердикта зависит от способа проверки, а не от предмета.** Три уровня:
   - `verified` — «верно / ошибка»: детерминированное сравнение с эталоном `trust=verified`;
   - `candidate` — «проверь слово X»: расхождение OCR с эталоном, непроверенный эталон или суждение LLM;
   - `feedback` — без вердикта: сочинения, свободные ответы.
   Ложная «ошибка» хуже пропущенной: при сомнении вердикт понижается (цель — ложных `verified` ошибок ≤ 5 %).
4. **Предмет — модуль с единым контрактом** (§4), а не ветка `if subject == ...`. Бот, онбординг,
   события, тьютор, сводки родителю — общие; модуль отвечает за распознавание, эталон, проверку и
   подсказки своего предмета.
5. **База знаний накапливается от работы, а не наполняется заранее.** Распознанные страницы учебников и
   выведенные ответы попадают в базу как непроверенные; ручная работа — подтвердить или поправить.
6. **Каждая форма задания открывается через стенд:** ≥ 10 реальных фото, метрики ложных «ошибок» и
   пропусков по силе вердикта, только потом флаг доступности в `bot/subjects.py`.

## 4. Контракт предметного модуля

Пакет `src/hwcheck/subjects/<code>/` (`math`, `russian`, `english`). Четыре шага, каждый — контракт
`(input) -> output` с pydantic-схемами, как существующие LLM-шаги (арх. §4):

```python
class SubjectModule(Protocol):
    code: str

    async def recognize(self, photos: list[bytes]) -> SubjectPage: ...
    async def resolve_reference(self, page: SubjectPage, kb: KnowledgeBase) -> list[Reference]: ...
    async def check(self, page: SubjectPage, references: list[Reference]) -> list[Finding]: ...
    async def hint(self, finding: Finding, level: int, kb: KnowledgeBase) -> Hint: ...
```

- `SubjectPage` — роль страницы (`textbook | notebook | unknown`), задания (номер, условие, ответ
  ученика), слова «как написано» с координатами (для кропов); для математики — то, что сейчас даёт
  `VisionPage`.
- `Reference` — эталон задания: `origin: photo | kb | derived`, `trust: verified | unverified`,
  содержимое по предмету (текст с заполненными пропусками, форма глагола, эталонное решение).
- `Finding` — находка: задание, позиция (слово/строка, координаты), `kind` (орфограмма, форма глагола,
  арифметика, пропуск слова…), `strength: verified | candidate | feedback`, `expected`, `actual`,
  `confirmed: bool | None` (ответ ученика на уточнение).
- `Hint` — текст подсказки уровня 0–3 с кодом правила из базы; уровень поднимает код (`bot/fsm.py`).

Роутинг — по `student_profiles.subject`; доступность — флаг `available` в каталоге. Общие части бота
(`bot/pages.py`, `bot/clarify.py`, `bot/check.py`, сводка, кнопки «Разобрать») работают с `Finding`.

**Математика переезжает в контракт без изменения поведения:** `recognize` = `recognize_photo` +
`split_pages`, `resolve_reference` = solver с кэшем, `check` = validator → `GradeResult` конвертируется в
`Finding` (`verified` для `correct/wrong`, `candidate` для `uncertain`), `hint` = tutor. Существующие
530 тестов проходят без правок логики.

## 5. База знаний

Одна база для всех предметов, PostgreSQL рядом с профилями (миграция `003_knowledge_base.sql`).

```sql
CREATE TABLE kb_pages (                  -- распознанная страница учебника
  id            bigserial PRIMARY KEY,
  subject       text NOT NULL,
  grade         smallint,
  fingerprint   text NOT NULL,            -- хэш нормализованного текста страницы
  text          text NOT NULL,            -- распознанный текст (печатный, не персональные данные)
  photo_path    text,                     -- var/kb_photos/..., хранится дольше тетрадей
  created_at    timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX kb_pages_fingerprint ON kb_pages (subject, fingerprint);

CREATE TABLE kb_tasks (                  -- задание со страницы
  id            bigserial PRIMARY KEY,
  page_id       bigint NOT NULL REFERENCES kb_pages ON DELETE CASCADE,
  number        text,                    -- «17», «3.9», «Упр. 42»
  condition     text NOT NULL,           -- условие с пропусками/скобками как в учебнике
  task_kind     text NOT NULL            -- fill_letters, expand_brackets, verb_form, choose, …
);

CREATE TABLE kb_answers (                -- наш эталон к заданию
  id            bigserial PRIMARY KEY,
  task_id       bigint NOT NULL REFERENCES kb_tasks ON DELETE CASCADE,
  answer        jsonb NOT NULL,          -- по task_kind: заполненный текст, форма, вариант
  derived_by    text NOT NULL,           -- dictionary | rule | llm:<модель>@<версия промпта>
  checked_by    text,                    -- dictionary | rule | manual
  status        text NOT NULL DEFAULT 'unverified'
                CHECK (status IN ('unverified', 'verified', 'rejected')),
  reviewed_at   timestamptz
);

CREATE TABLE kb_rules (                  -- карточка правила для тьютора
  code          text PRIMARY KEY,        -- ru.orth.unstressed_vowel, en.verb.past_simple
  subject       text NOT NULL,
  grade_from    smallint NOT NULL,
  title         text NOT NULL,
  statement     text NOT NULL,           -- формулировка для ребёнка
  example       text NOT NULL,
  finding_kinds text[] NOT NULL          -- какие находки к нему ведут
);

CREATE TABLE kb_words (                  -- словари
  subject       text NOT NULL,
  word          text NOT NULL,
  source        text NOT NULL,           -- hunspell | grade_list:<класс> | textbook_unit | irregular_verbs
  attrs         jsonb,                   -- формы глагола, класс, юнит
  PRIMARY KEY (subject, word, source)
);
```

- **Поиск страницы:** по `fingerprint` (нормализованный текст → sha256). Нечёткий поиск (эмбеддинги)
  — только когда точный перестанет справляться; не раньше.
- **Узнавание по тетради:** если ребёнок списал текст упражнения, выравнивание с `kb_tasks.condition`
  той же темы даёт эталон без фото учебника (вторая очередь, после 15.10).
- **Сила эталона:** `verified` — `kb_answers.status = 'verified'` или `checked_by IN ('dictionary',
  'rule')`; иначе `unverified` → вердикт не выше `candidate`.
- **Наполнение правил и словарей** — заранее: Hunspell ru/en (открытые словари), списки словарных слов
  по классам, неправильные глаголы; карточки правил — LLM-черновик по программе класса, вычитка Claude,
  затем Кирилла. Лексика по юнитам — из распознанных страниц учебника.
- **Ручная проверка:** `hwcheck kb review [--subject]` — консольная очередь непроверенных ответов:
  условие, наш ответ, кроп/фото страницы; действия `y / n / правка`. Веб-интерфейс — вне объёма.
- **Не делаем:** парсинг учебников целиком, ГДЗ, хранение фото тетрадей в базе.

## 6. Русский язык — минимальная форма

**Форма:** «спиши, вставь пропущенные буквы / раскрой скобки», 1–6 класс (в 1–4 фото присылает родитель).

**Распознавание.** Тетрадь → ReadingPipeline (ai-forever, MIT): сегментация строк и слов + CRNN без
языковой модели → слова с координатами. Учебник → GigaChat-vision (печатный текст с пропусками
`м_шина`, `(с)делать`).

**Эталон.** Пропуск заполняется по Hunspell ru: ровно одно словарное слово под шаблон → `derived_by=
dictionary`, `trust=verified`; несколько или ноль → GigaChat выбирает, `derived_by=llm`, статус
`unverified`, очередь ручной проверки. Скобки (слитно/раздельно, приставка/предлог) — так же.

**Проверка.** Выравнивание слов тетради с эталоном (Левенштейн по словам, затем по буквам). Находки:

| Ситуация | Сила | Текст ребёнку |
|---|---|---|
| слово совпало | — | верно |
| расхождение в позиции пропуска, эталон `verified` | `candidate` → уточнение | «здесь написано *машына*?» + кроп, кнопки да/нет; «да» → `verified` ошибка, «нет» → снята |
| расхождение вне пропуска | `candidate`, ниже приоритет | то же, если хватит лимита; иначе в сводке «ещё N мест перепроверить» |
| пропущено/лишнее слово | `candidate` | «кажется, пропущено слово после …» |

Лимит уточнений — 2–3 на домашку (как `bot/clarify.py`).

**Тьютор.** Код орфограммы — GigaChat по паре «слово + эталон» (классификатор, как `classify_error`);
правило — из `kb_rules` по коду. Уровни: 0 «какая здесь орфограмма?», 1 правило, 2 пример, 3 написание.

**Не входит:** диктанты, сочинения, разбор слова, морфология, пунктуация — позже, через `feedback`.

## 7. Английский язык — минимальная форма

**Форма:** упражнения с однозначным коротким ответом, 2–7 класс: вставь слово из рамки, форма глагола
(раскрой скобки), выбери вариант, допиши окончание. Ребёнок пишет предложение целиком или ответ с
номером — выравнивание по номерам.

**Распознавание.** Тетрадь → посимвольный OCR латиницы. Спайк 17.09: GigaChat читает латиницу точно
(80 % слов), но исправляет 100 % ошибок ученика, а расхождение двух расшифровок как сигнал бесполезно
(полнота 7 %); TrOCR по кропам сохраняет лишь 14 % ошибок. Путь этапа 4 — ReadingPipeline на латинице
(не измерен), резерв — сегментация ReadingPipeline + TrOCR по слову. **Сила вердикта английского на
старте — только `candidate`**, `verified` открывается только по стенду.

**Эталон.** Форма глагола — по правилу (правильные `-ed`/`-s`/`-ing`) и таблице неправильных из
`kb_words` → `derived_by=rule`, `trust=verified`. Выбор из рамки — LLM, результат обязан быть словом из
рамки; единственный подходящий → `verified`, иначе `unverified`.

**Проверка.** Сравнение ответа с эталоном по позиции пропуска: совпало — верно; расходится при
`verified` эталоне и уверенном OCR (уверенность распознавания слова выше порога, который задаёт стенд
по доле ложных срабатываний) — `verified` ошибка; иначе `candidate` с кропом и вопросом «здесь написано
*goed*?». Опечатка при верной форме (одна буква, слово словарное) — находка «форма верна,
проверь написание».

**Тьютор.** Коды: время/форма глагола, артикль, множественное число, порядок слов, орфография. Уровни:
0 «какое время? найди подсказку», 1 правило из базы по юниту, 2 пример с другим глаголом, 3 ответ.

**Не входит:** перевод, ответы по тексту, сочинения и письма — `feedback` после 15.10.

## 8. Общие части бота

**Сводка ученику** — одна форма для всех предметов: «Проверил! N из M верно»; по заданию — «верно ✅» /
«есть ошибка ❌ (слово *машына*)» / «стоит перепроверить 🤔 (2 места)» / «разобрал, оценки нет 📝».
Кнопки «Разобрать» — для `verified` ошибок и подтверждённых `candidate`.

**Уточняющие вопросы** — `bot/clarify.py` получает вид `word`: кроп слова + «здесь написано …?» с
кнопками да/нет. Кроп требует отправки изображения в MAX (`POST /uploads` + вложение в сообщении) —
задача каркаса; без неё вопрос текстом.

**Родителю (этап 4 онбординга):** счётчики по предметам: верно / ошибок / перепроверить.

**Данные.** `homeworks.subject` есть. Новая таблица `findings` (домашка, задание, `kind`, `strength`,
`confirmed`, `resolved`) — основа аналитики качества и будущей модели ученика (`skill_states`, арх.
§6.1). Фото учебников — `var/kb_photos`, срок хранения дольше тетрадей (не персональные данные ребёнка);
указать в политике.

**События:** `finding_created{subject, kind, strength}`, `finding_confirmed{answer}`,
`reference_resolved{origin, trust}`, `kb_review{action}`. Доля «нет» в `finding_confirmed` — мера
ложных срабатываний OCR по предмету.

**Инфраструктура.** OCR — отдельный контейнер `homework-ocr` (CPU, ONNX, HTTP внутри compose-сети,
без портов наружу); бот ходит к нему как к GigaChat: таймаут 60 с, при недоступности —
`candidate`/«не уверен», событие `ocr_failed`. **Память (спайк 17.09):** ReadingPipeline даёт пик
~3 ГБ на страницу (лимит 2 ГБ убивается OOM), поэтому лимит контейнера ≥ 3 ГБ. На общем VPS с
~3,7 ГБ доступной памяти это возможно только после апгрейда до 16 ГБ или после снижения пика
(ONNX/OpenVINO без torch-аллокатора — не проверено); иначе OCR размещается в Cloud.ru раньше
остального. Решение — до этапа 3.

**Тесты.** Контрактные тесты модуля на фейках (страница + эталон → находки) для каждого предмета;
математика проходит их после переезда. Стенд `bench/` — golden-кейсы по предметам (фото тетради, фото
учебника, ожидаемые находки), метрики ложных «ошибок» и пропусков по силе вердикта. Порог открытия
предмета: ложных `verified` ошибок ≤ 5 % на ≥ 10 реальных фото.

## 9. Спайки (до реализации, 2–3 дня, параллельно)

1. **ReadingPipeline на VPS:** Linux-контейнер, CPU, ONNX; время на страницу, память; качество на
   5–10 фото из MAX (пережатые до 1280 px). Итог: лимит контейнера, таймаут, решение «на VPS или в
   Cloud.ru».
2. **Заполнение пропусков по Hunspell:** 30 упражнений учебников 2–4 класса; доля однозначных
   заполнений. Итог: ожидаемая доля `verified` эталонов.
3. **OCR латиницы:** 20 листов `ai-forever/school_notebooks_EN`; (а) ReadingPipeline с русскими весами,
   (б) TrOCR-handwritten (Microsoft, MIT) на CPU, (в) GigaChat две расшифровки. Метрики как в
   исследовании 13.09: доля сохранённых ошибок ученика, скрытых, CER. Итог: путь и сила вердикта
   английского на старте.

## 10. Порядок работ до 15.10

| Шаг | Срок | Результат |
|---|---|---|
| Спайки §9 | 2–3 дня | решения по OCR и силе вердиктов |
| Каркас | ≈ неделя | контракт модуля, математика в контракте, миграция базы знаний, `Finding` в сводке и уточнениях, контейнер OCR, отправка кропов |
| Русский | ≈ неделя | модуль, Hunspell, правила орфограмм 2–4 класса, стенд ≥ 10 фото, флаг |
| Английский | ≈ неделя | модуль, глаголы, правила времён 3–6 класса, стенд, флаг |
| Ручная проверка базы | с первого дня русского | `hwcheck kb review` |

Три недели разработки при параллельных онбординге (этапы 3–5), интервью и привлечении пользователей.
При нехватке времени откладываются по порядку: `verified` для английского, кропы слов, узнавание страницы
по тетради.

## 11. Риски и открытые вопросы

- **OCR латиницы** — может не собраться к сроку; запасной путь даёт только `candidate`.
- **Память VPS:** контейнеру OCR нужно ≥ 3 ГБ (спайк 17.09), на общем хосте с 8 ГБ и 4 ГБ swap это впритык — апгрейд до 16 ГБ, Cloud.ru или снижение пика памяти; см. §8.
- **Ложные срабатывания OCR (17–24 % верных слов)** — снимаются уточнениями, но каждое уточнение — трение
  для ребёнка; лимит 2–3, остальное в сводку. Мерить долю «нет».
- **Правила по классам** — ручная вычитка карточек; черновик LLM может расходиться с программой конкретного
  учебника.
- **Авторские права** — храним распознанные условия заданий из фото пользователей и наши ответы; не
  копируем учебники и не парсим ГДЗ. Показать юристу вместе с политикой.
- **Кропы слов** — отправка изображений через API MAX не проверена живьём.
- **Спецификация онбординга §5:** флаги `available` для `russian` и `foreign_language` меняются при
  открытии; лист ожидания получает рассылку (вне объёма этого документа).
