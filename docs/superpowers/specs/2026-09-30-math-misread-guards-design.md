# Математика: ошибка чтения — не ошибка ребёнка. Дизайн

Дата: 2026-09-30. Статус: направление согласовано с Кириллом в чате 30.09 («да, начинай»), текст ждёт
вычитки. Связанные документы: `docs/architecture.md` §3.3 и §7, `docs/superpowers/specs/2026-09-16-subjects-framework-design.md`
§3 (сила вердикта).

## 1. Что случилось

Живая проверка тестера 30.09 (№ 2.181 из учебника, четыре пункта; состояние чата снято с прода):

| Пункт | В тетради | Как прочитано | Что решил код |
|---|---|---|---|
| а) | `39454 − 16452 : (300 − 264) = 38997` (в учебнике 39 452, ответ 38 995) | `9454 − … = 8997` | «верно»: обе потерянные цифры сошлись |
| б) | итог не дописан, `27252` — второе частное | `2558304 : 63 + 16623 * 42 : 61 = 27252` | ошибка, верное значение `3175254/61` |
| в) | `… = 7658`, верно | `93601 − 667 * (231 − 88) = 7658` | ошибка, верное значение `−1780` |
| г) | не дорешан | без результата | пропущен |

Сводка показала «есть ошибка (строка 2)», разбор ждал число `3175254/61` — ввести его ребёнок не может.
Настоящая ошибка (пункт а) пропущена, две «подтверждённые» ошибки — артефакты чтения рукописи.

Причина: в задании из пунктов вердикт ставит пересчёт каждой строки (`grade_by_lines`), а любое
расхождение строки — `verified`-ошибка. Печатное условие того же пункта при этом было в руках (фото
учебника) и не использовалось.

## 2. Решения

| Вопрос | Решение |
|---|---|
| Чему верить, когда строка тетради расходится с печатным условием пункта | Выражение берём из условия, из тетради — только записанный результат |
| Строка не совпала ни с условием, ни с его значением | Не «ошибка», а «не уверен» с причиной `line_misread`; дальше — вопрос ребёнку (этап B) |
| Расхождение с невозможным «верным значением» | То же «не уверен»: школьный пример на целые числа не даёт `3175254/61` |
| Где живёт логика | Отдельный проход после `check_steps` — `pipeline/reading.py`; валидатор остаётся чистым пересчётом (им же проверяются эталоны солвера и генератора — там послаблений быть не должно) |
| Порядок | Этап A (вердикт) → этап B (вопрос). Два PR |

## 3. Этап A — вердикт

### 3.1. Пункты печатного условия

`printed_items(condition) -> dict[str, PrintedItem]`: метка пункта → выражение, его значение (SymPy) и число
действий.

- Метка — одна буква или число до двух цифр со скобкой (`а)`, `1)`) в начале текста или после пробела
  и знаков `; : . ,`, вне скобок выражения (`(5244 : 19 : 12)` не даёт метку `12)`).
- Текст пункта — до следующей метки. Пробелы в разрядах убираются (`39 452` → `39452`); хвостовые
  `; . ,` отбрасываются.
- Пункт годится, только если весь его текст — числовое выражение хотя бы с одним действием: без букв
  и без `=`. «а) 27 · 3 и 38 − 19», буквенные выражения, равенства — не пункты для сверки.
- Метка встретилась дважды — пункт не используется.
- Латинские `a`, `e` в метке строки тетради приравниваются к кириллическим (распознавание пишет `a)`).

### 3.2. Сверка строки с пунктом

Для строки со статусом `ok` или `mismatch`, с меткой пункта, без переменной, у которой в левой части
действий не меньше, чем в печатном выражении (то есть ребёнок переписал пример целиком, а не одно
действие):

1. записанный результат равен значению печатного выражения → `ok`, как бы ни прочиталась левая часть;
2. иначе левая часть по значению равна печатному выражению → `mismatch` (обычная арифметическая
   ошибка, цель разбора — значение печатного выражения);
3. иначе → `skipped`, `doubtful`, `misread`: пример переписан с ошибкой или прочитан неверно, по одной
   строке это не различить.

Строка-действие («300 − 264 = 36» под пунктом из трёх действий) и строки без метки проверяются как
раньше.

### 3.3. Невозможное значение

Для оставшихся `mismatch` без переменной — «не уверен» (`skipped`, `doubtful`, `misread`), если верное
значение строки:

- дробь, не представимая конечной десятичной (в знаменателе есть множитель кроме 2 и 5), а в строке нет
  ни дробной черты, ни десятичной запятой;
- отрицательное, при этом записанный результат неотрицателен, не равен ему по модулю, и в строке нет
  отрицательных чисел.

«12 − 20 = 8» (ошибка знака), «7 : 2 = 3» (верное 3,5) и строки с дробями остаются ошибками.

### 3.4. Вердикт и тексты

- `LineCheck.misread: bool = False` — поле с умолчанием, старые записи Redis читаются.
- `UncertainReason` пополняется `line_misread`; в `_uncertain_reason` она идёт сразу после `unreadable`.
- Текст причины в сводке: «не уверен, что верно прочитал запись».
- Проход применяется к работе ученика (`grade`, `validator_only_grade`), не к самопроверке эталона.

Тот же случай после этапа A: а) и б) — «не уверен», в) — верно, г) — пропущен; задание — «не уверен, что
верно прочитал запись», ложной ошибки и недостижимой цели разбора нет.

## 4. Этап B — вопрос вместо «не уверен»

- `LineCheck.printed: str | None` — печатное выражение пункта у `misread`-строки.
- Новый вид вопроса `result`: «№…, пункт а): я прочитал пример как «39452 − 16452 : (300 − 264)». Какой
  ответ у тебя получился? Напиши числом». Эталон вопрос не раскрывает.
- Ответ → строка заменяется на «а) <печатное выражение> = <число>» и пересчитывается: совпало — верно;
  не совпало — `verified`-ошибка с целью разбора «значение печатного выражения».
- Ответ равен значению строки, как она записана у ребёнка, но не печатному — ошибку не утверждаем
  (печатное условие тоже могло прочитаться неверно): «сходится с твоей записью, но в учебнике я вижу
  другой пример — сверь запись».
- `misread`-строка без печатного пункта — существующий вопрос «перепиши строку».
- В одном задании спрашиваем все такие строки в пределах общего лимита (`MAX_QUESTIONS`).

- Регрессия: строки и условие живой проверки 30.09 целиком — вердикт «не уверен», причина

- Прежние тесты `test_multipart.py`, `test_grade.py`, `test_long_division.py`, `test_solver.py` проходят
  без правок.

## 6. Чего здесь нет

- Сверка строк без метки пункта со списком примеров условия («651 + 126; 379 − 253»).
- Ответы без записи решения («а) 38995»).
- Класс ученика как параметр правил (отрицательные числа с 6 класса).
- Разбор и сводка — отдельные спецификации: вопрос тьютора от кода, разбивка по пунктам, «что дальше».
