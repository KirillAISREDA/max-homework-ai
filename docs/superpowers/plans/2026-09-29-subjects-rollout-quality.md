# Остальные предметы и качество ≥ 95 % — план (дорожная карта)

> **For agentic workers:** это план-карта, а не план с кодом: задачи, файлы, критерии приёмки и ворота стенда. Код для каждого этапа пишется отдельным планом по коду предыдущего (как `2026-09-17-russian-stage3.md` написан по коду каркаса) и проходит ревью каждой задачи + финальное + безопасность. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** в проде проверяются все предметы каталога `bot/subjects.py` (1–9 классы), а вердикт «ошибка» верен не менее чем в 95 % случаев по каждому предмету. Порядок открытия — по цене и ценности: русский → предметы с вычислениями (физика, химия, информатика) → гуманитарные в форме разбора без оценки → английский. Ни один предмет не открывается без стенда на реальных фото.

**Architecture:** «95 %» — свойство политики вердиктов, а не модели. Распознавание рукописи сегодня не даёт и 80 % (GigaChat-2-Max: 37 из 51 строки-вычисления с расхождением, стенд 14.09; лучшие модели шлюза: CER 44–47 % на трудных страницах, стенд 28.09), поэтому «ошибка» ставится только детерминированной сверкой с проверенным эталоном (`strength=verified`), а всё остальное уходит ребёнку вопросом с кропом (`candidate`) или разбором без оценки (`feedback`) — спецификация каркаса §3. Каждый новый предмет — модуль контракта `SubjectModule` (`recognize → resolve_reference → check → start_tutoring`), а не ветка в боте; общий стенд с одним набором метрик — ворота флага `available`. Два рычага, общих для всех предметов: модель чтения фото (уже переключается по согласию родителя через `vision_override`) и уточняющий вопрос перед вердиктом «ошибка».

**Tech Stack:** как в каркасе — Python 3.12, pydantic, PostgreSQL 17 (база знаний `kb_*`, `findings`), Redis, GigaChat API (чтение фото без согласия на стороннюю модель) + шлюз организаторов (`gw:<модель>`; текстовые шаги, при согласии v2 — чтение фото), ReadingPipeline в `ocrsvc/` (языки), SymPy (математика и предметы с вычислениями), `spylls`/Hunspell, стенд `bench/`.

**Spec:** `docs/superpowers/specs/2026-09-16-subjects-framework-design.md` (§3 принципы, §4 контракт, §5 база знаний, §6 русский, §7 английский, §8 общие части бота). Стенды: `bench/README.md`, `bench/golden_ru/README.md`, `bench/reports/2026-09-14-models.md`, `bench/reports/2026-09-18-russian.md`, `bench/reports/2026-09-28-gateway.md`. Спайки: `docs/research/2026-09-13-ru-handwriting-ocr.md`, `…-2026-09-17-hunspell-gaps.md`, `…-2026-09-17-en-handwriting-ocr.md`, `…-2026-09-17-readingpipeline-memory.md`.

## Global Constraints

- **Метрика качества — три числа, а не одно.** Иначе 95 % достигаются бесплатно вердиктом «не уверен» на всё.
  1. **Ложные «ошибки» ≤ 5 %** — доля вердиктов `verified`-ошибка (и подтверждённых `candidate`), под которыми на фото верная запись. Это и есть «качество ≥ 95 %» и порог запуска из `docs/architecture.md` §11.
  2. **Покрытие ≥ 70 %** — доля заданий тетради, получивших вердикт «верно»/«ошибка», а не «не уверен»/«перепроверь». Отчётная метрика с порогом по предмету: у математики сейчас 58–67 % верных вердиктов при 17 % «не уверен» (стенд 14.09); у языков покрытие считается по ответам ребёнка на вопросы.
  3. **Точность кандидатов в первых двух вопросах ≥ 50 %** — доля «здесь написано …?», указывающих на настоящую ошибку (`bench/golden_ru`). Мера трения, а не качества вердикта.
- **Сила вердикта по способу проверки** (спецификация §3): `verified` — только детерминированная сверка с эталоном `trust=verified`; суждение LLM — не выше `candidate`; свободный текст — `feedback`. При сомнении вердикт понижается. Правило не обходится ни для одного предмета «ради покрытия».
- **Ворота флага:** ≥ 10 реальных фото формы задания в golden (цель — 30), ложных `verified` ≤ 5 %, точность кандидатов ≥ 50 %, прогон тем же кодом, что в боте (`hwcheck bench …`). Спорные вердикты с прода уходят в golden каждую неделю (`var/photos`, правило памяти §9).
- **Персональные данные (152-ФЗ):** фото детей — сторонней модели только при согласии родителя по политике v2 (уведомление Роскомнадзора до начала передачи); стенд сторонних моделей — только открытый датасет; golden-кейсы с ФИО/школой/адресом в репозиторий не кладутся; фото — локально.
- **Вехи конкурса главнее:** до 14.10 новые предметы не открываются и не забирают время Кирилла у 50 семей и 20 интервью. До 14.10 делается только то, что не требует его участия (Task Q1, Q3, Q4-код, R1) и решения, которые нужны в любом случае (Task Q2).
- **Математика не меняет поведения** от общих задач Q1–Q4: существующие тесты проходят без правок логики, тексты сводки ученику прежние; изменения вердиктов — только через стенд.
- Обращения конкурса: новые вызовы модели (второй взгляд на кроп, вторая расшифровка) считаются в `llm_call` и в стоимость проверки; цель — не дороже ×1,5 текущей проверки на домашку.

### Task S1–S4: Физика, химия, информатика на математическом ядре

Расчётные задания 7–9 классов проверяются тем же путём, что математика: эталон солвера → пересчёт SymPy → `verified`. Источник истины детерминированный, поэтому качество наследуется от математики. Качественные вопросы («почему…») — `feedback` (модуль этапа C).

- [ ] **S1. Модуль `subjects/science/`:** `ScienceModule(subject)` поверх `MathModule` — `recognize` тот же двухэтапный vision с промптом структуризации, знающим «Дано / Найти / Решение / Ответ» и единицы; `resolve_reference` — солвер с промптом предмета (`prompts/solver_physics/v1.md` и т. д.), эталон обязан содержать формулу, подстановку, ответ с единицей; `check` — `grade` + проверка единиц; `start_tutoring` — тьютор с карточками правил предмета.
- [ ] **S2. Валидатор:** единицы и размерности (`pipeline/validator.py`: СИ-префиксы, перевод км/ч ↔ м/с, г ↔ кг; расхождение единицы при верном числе — `candidate` «проверь единицу»); химия — уравнивание реакций и молярные массы детерминированно (SymPy: линейная система по коэффициентам, таблица масс в `assets/kb/atomic_masses.json`); информатика — системы счисления, логические выражения, объём информации — детерминированно, без солвера.
- [ ] **S3. Карточки правил и промпты:** `rules_physics.json` (формулы 7–9 по темам), `rules_chemistry.json`, `rules_informatics.json` — черновик LLM по ФОП ООО, вычитка; классификатор ошибки: `formula_choice | substitution | units | arithmetic`.
- [ ] **S4. Стенд и флаг:** `bench/golden_physics/` и др. по формату `bench/golden/` (тетрадь + учебник/задачник), ≥ 10 фото на предмет из Task Q4; гейт Q1; флаги `physics`, `chemistry`, `informatics` только для расчётных форм — качественный вопрос модуль распознаёт по отсутствию чисел в решении и отдаёт этапу C.

**Приёмка:** ложных «ошибок» ≤ 5 % и покрытие ≥ 60 % на golden каждого предмета; живой тест на задаче с единицами (км/ч → м/с) и на уравнении реакции.

### Task H1–H4: Гуманитарные предметы — разбор без оценки

Формы домашки: ответы на вопросы к параграфу, пересказ, таблица, определения, даты. Однозначного эталона для большинства нет → сила `feedback`: бот не ставит «ошибка», а разбирает «что дополнить/уточнить» по тексту параграфа. Ложных ошибок нет по построению; ценность — экономия времени родителя и «понял ли параграф».

- [ ] **H1. Модуль `subjects/reading/`** (один для `world_around`, `history`, `biology`, `geography`, `social_studies`, `literature`, `literary_reading`): `recognize` — vision читает вопросы/параграф учебника и ответы тетради (для `feedback` LLM-vision допустим: вердикта нет, «исправление» ребёнка не искажает разбор — спецификация §3 п. 2); `resolve_reference` — параграф/вопросы → `kb_pages`/`kb_tasks` (`task_kind=question`), эталон `trust=unverified`; `check` — LLM по схеме: по каждому вопросу `covered | partial | off_topic | missing` + что дополнить, всё `strength=feedback`; `start_tutoring` — уровни 0–3: «о чём спрашивают» → «где в параграфе» → «с чего начать ответ» → пример ответа.
- [ ] **H2. Сводка ученику и родителю:** «разобрал, оценки нет 📝» уже в сводке (спецификация §8); родителю — «ответил на 4 из 5 вопросов, стоит дополнить №3»; в `homeworks` — без «верно/ошибка».
- [ ] **H3. Формы с однозначным ответом → `candidate`:** тест с выбором (буква/номер), даты, термины, «заполни таблицу» — эталон из базы знаний (`kb_answers`, `derived_by=llm`, очередь `kb review`), сравнение детерминированное (строка/число/дата), сила `candidate` до подтверждения ревьюером (`status=verified` → `verified`); модуль определяет форму по условию.
- [ ] **H4. Стенд и флаг:** golden по 10 фото на предмет; метрика этапа — оценка полезности разбора Кириллом/родителем (по 10 фото ≥ 8 полезных), ложных «ошибок» — 0 по построению (проверяется гейтом: модуль не выдаёт `verified`); флаги по предметам по мере фото; тексты онбординга «проверка без оценки» — честно в приветствии предмета.

**Приёмка:** гейт: 0 `verified` от модуля; на 10 фото истории/окружающего мира разбор признан полезным ≥ 8 раз; стоимость проверки не выше математической.

### Task F1–F4: Своя модель чтения — открытая VLM, дообученная на тетрадях, в РФ

Единственный путь «дообучить под детские каракули»: у закрытых моделей шлюза его нет. Побочный эффект важнее самого дообучения — фото детей не покидают РФ, политика v2 и уведомление Роскомнадзора для чтения фото становятся не нужны, модель учится на ошибках из `review_queue`.

- [ ] **F1. Спайк хостинга и базовой точности (2–3 дня):** Qwen3-VL 8B и 32B (открытые веса, Apache-2.0 — сверить лицензию на момент старта) на GPU Cloud.ru Evolution (или другом хостинге в РФ), OpenAI-совместимый сервер (vLLM); прогон `bench run` с промптом `v4-qwen` на 30 golden-страницах; замер: «не найдено», ложные «ошибки», CER, время, ₽/страница с учётом аренды. Параллельно: **спросить организаторов, где физически работает Qwen3-VL на их шлюзе** — если в Москве, это путь без юриста уже сейчас.
- [ ] **F2. Датасет дообучения:** `school_notebooks_RU` (построчная разметка, MIT) → пары «кроп строки/страница → транскрипция как написано»; ваши фото — только с согласием на использование для улучшения качества (Task Q4, политика v2); целевой объём 1–3 тыс. страниц; валидационный срез — golden 30 + живые фото, в обучение не попадает.
- [ ] **F3. LoRA-дообучение** на задачу транскрипции (без исправления ошибок ученика — контроль: доля сохранённых ошибок ученика ≥ 90 % на валидации, как в исследованиях 13.09/17.09); повтор F1-замера; модель хранится в Artifact Registry Cloud.ru, веса — не в git.
- [ ] **F4. Подключение:** `VISION_MODEL=<своя>` через ту же абстракцию `gw:`/OpenAI-совместимый клиент, `VISION_MODEL_DOMESTIC` = своя (фото не покидают РФ) — политика упрощается; GigaChat остаётся запасным путём; стоимость на DAU — в отчёт `report cost`.

**Риски:** GPU-аренда десятки тысяч ₽/мес при малом трафике — оправдана только при DAU зачётного периода (≥ 1000) или требовании закона; Qwen3-VL 235B на стенде 28.09 показал «не найдено» 8/15 без промпта под него — младшие модели без дообучения будут хуже, обещать цифры нельзя до F1.

## Риски

- **Фото не приходят** → этапы стоят. Смягчение: Q4 в боте с первого дня пилота, просьба на интервью.
- **Юрист/Роскомнадзор затягиваются** → чтение фото остаётся на GigaChat; языки и гуманитарные не зависят от этого (OCR и печатный учебник), математика и предметы с вычислениями теряют главный рычаг покрытия — тогда Q3 (вопросы) становится основным.
- **ReadingPipeline не читает латиницу** → английский только резервным путём (`candidate`, TrOCR), срок +1 неделя.
- **Стоимость проверки** растёт с вторым взглядом и второй расшифровкой → лимит ×1,5 в Global Constraints; отчёт `report cost` на каждом этапе.
- **Гуманитарные без оценки могут не удержать** → мерить D7 по предмету против математики; если ниже вдвое — H3 (формы с ответом) в приоритет.
