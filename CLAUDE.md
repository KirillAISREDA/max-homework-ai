# max-homework-ai

AI-проверка домашней работы в мессенджере MAX. Инфраструктура: Cloud.ru Evolution. LLM/vision: GigaChat API.

## Старт каждой сессии (обязательно)

1. Прочитай `docs/PROJECT_MEMORY.md` — продукт, текущее состояние, решения, артефакты, грабли.
2. Прочитай `TODO.md` и пройди его чек-лист «Старт сессии» (раздел «Сейчас», план недели, прод, PR).
3. Прочитай последнюю запись `HISTORY.md` (весь файл — только если нужна история решения).
4. Сверься с `docs/architecture.md` и спецификациями `docs/superpowers/specs/` при работе над компонентом.

## Конец каждой сессии (обязательно)

- Допиши в `HISTORY.md` запись о сессии: дата, что сделано, принятые решения, открытые вопросы.
- Обнови `TODO.md`: убери выполненное, добавь новое, поправь план недели.
- Обнови `docs/PROJECT_MEMORY.md`, если изменились состояние, решения, артефакты или появились новые грабли.

## Ключевые архитектурные инварианты (не нарушать)

- Webhook MAX отвечает мгновенно; вся тяжёлая работа — асинхронно через очередь (Redis).
- Математика валидируется детерминированно (SymPy). LLM — не источник истины по арифметике.
- FSM диалога управляется кодом, не LLM. Ответ ученику раскрывается только на hint_level 3.
- Все LLM-шаги — единый контракт `(input: dict) -> dict` с JSON Schema; модель/промпт меняются без переписывания.
- Промпты — версионированные файлы в `prompts/`, версия пишется в БД с каждым результатом.
- Персональные данные детей минимизированы (152-ФЗ): без ФИО/школы, `max_user_id` шифруется.

## Стек

- Python 3.12+, FastAPI, arq/Celery поверх Redis, PostgreSQL, SymPy, pydantic.
- Деплой: контейнеры → Cloud.ru Evolution (Container Apps на пилоте, Managed Kubernetes дальше).
