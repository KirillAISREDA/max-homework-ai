# Стенд русского языка

Замеряет `RussianModule` (спецификация §6) на **реальных фото** «страница учебника + страница
тетради» — тем же кодом, что работает в боте, через `hwcheck bench ru`. Для русского `verified`
без подтверждения ребёнка не ставится, поэтому главные метрики — не «ложные ошибки», а:

- **точность кандидатов в первых двух** — доля вопросов «здесь написано …?» в пределах
  `MAX_QUESTIONS`, которая указывает на настоящую ошибку ребёнка;
- **полнота в первых двух** — спросит ли бот про настоящую ошибку среди первых `MAX_QUESTIONS`
  вопросов (отчётная метрика, не порог).

Порог открытия формы задания: ложных `verified` = 0 (по построению — русский их не ставит) **и**
точность кандидатов в первых двух ≥ 50 % на ≥ 10 фото.

- `bench/golden_ru/*.json` — эталонная разметка (в репозитории). Фото в git **не хранятся**:
  разметка ссылается на них по sha256, сами фото лежат локально в `data/` (в `.gitignore`), как в
  `bench/README.md`.
- `bench/reports/*.md` — отчёты прогонов (без фото и без слов из тетрадей).
- Кэш ответов моделей — `.cache/bench/llm/` (повторный прогон не тратит токены); JSONL прогона —
  `.cache/bench/runs/russian.jsonl` (в git не попадает: там слова из тетрадей).

## Формат эталона (`schema: 1`)

Один файл — один **кейс**: альбом из фото страницы учебника («вставь буквы») и страницы тетради
с решением ребёнка.

```json
{
  "schema": 1,
  "id": "ru-01",
  "source": "Кирилл, 17.09.2026: учебник рус. яз. 3 кл. упр. 245 + тетрадь",
  "photos": [
    {"sha256": "<64 hex>", "role": "textbook"},
    {"sha256": "<64 hex>", "role": "notebook"}
  ],
  "exercise": {"number": "245", "text": "Наступила п_здняя ос_нь."},
  "reference": "Наступила поздняя осень.",
  "errors": [
    {"written": "позняя", "expected": "поздняя", "in_gap": true}
  ],
  "notes": ""
}
```

Поля:
- `photos[].role` — `notebook` (решение ученика), `textbook` (печатная страница учебника с
  пропусками), `empty` (нечитаемо, не по теме, пустая страница). Роль здесь — то, что видит
  разметчик по фото; сам стенд гоняет реальное распознавание роли модулем и не полагается на
  это поле при подсчёте — оно только для навигации по кейсу человеком.
- `exercise` — упражнение **как в учебнике**, с пропусками (`number` — если написан, иначе `null`).
  Справочное поле, пока в кейсе есть фото учебника: не участвует в подсчёте метрик, только
  помогает разметчику и ревьюеру видеть условие рядом с ошибками.
  **Кейс без учебника** (только фото тетради — так приходят живые фото: упражнение диктует
  учитель, текст набирает родитель) — эталон набирается вручную, и `exercise.text` = текст
  упражнения: стенд берёт его единственным условием вместо страницы учебника (с пропусками `_`,
  если они есть; для «спиши» это сам эталонный текст). `number` — только если номер и правда
  написан в упражнении, иначе `null`.
- `reference` — тот же текст с заполненными пропусками, правильный вариант. Тоже справочное поле.
- `errors` — **только настоящие ошибки ребёнка**, проверенные разметчиком по фото тетради
  (сверка с `reference`, а не с моделью):
  - `written` — слово как его написал ребёнок (с ошибкой);
  - `expected` — правильное слово (из `reference`);
  - `in_gap` — ошибка в позиции пропуска учебника (`_`); `false` — ошибка вне пропуска
    (например, в слове, которое в учебнике дано целиком).
  - Правильно написанные слова, даже в пропуске, в `errors` не попадают — только ошибки.
- `notes` — всё важное для интерпретации (плохо видно почерк, ребёнок исправил сам, наклон фото).

## Запуск

```bash
uv run python -m hwcheck bench ru --golden bench/golden_ru --photos data \
  --ocr-url http://127.0.0.1:8080 --out bench/reports/<дата>-russian.md
```

- OCR-сервис (R1) должен быть поднят и слушать `--ocr-url` (по умолчанию
  `http://127.0.0.1:8080`) — на VPS: `docker compose --profile ocr up`, локально — тот же образ.
- `--max-calls` — лимит свежих вызовов GigaChat на прогон (кэш общий с математическим стендом
  устройством, но каталог свой: `.cache/bench/llm/`).
- База знаний — `InMemoryKnowledgeBase()`: прогон стенда не пишет в прод-базу.
- Кейсы разбираются в порядке файлов; при отсутствии фото в `--photos` — `SystemExit` со списком
  недостающих (как у `hwcheck bench run`).

### Сбой кейса (`error` в JSONL)

`RussianModule.recognize()` не бросает исключение ни на сбое OCR, ни на нераспознанной странице —
без явных проверок такой кейс тихо считался бы «ошибок нет» (пустой notebook). Поэтому строка
кейса в `.cache/bench/runs/russian.jsonl` может нести `error`:
- `ocr_failed` — хотя бы одна страница вернула `failure="ocr_failed"` (OCR-сервис недоступен или
  не прочитал фото);
- `no_notebook` — среди распознанных страниц не нашлось ни одной тетради с заданиями (пустой
  альбом, только учебник, или страницу не распознали вовсе — `role="unknown"`);
- `no_reference` — эталон не вывелся ни из одного условия (условие не разобралось; в кейсе без
  учебника — пустой `exercise.text`);
- `ИмяИсключения: сообщение` — любой другой сбой пайплайна (`recognize`/`resolve_reference`/
  `check` подняли исключение).

Кейс с заданным `error` уходит в `RuSummary.failed` (в отчёте — «Кейсов (+ упавших)»), в метрики
точности/полноты не попадает.
